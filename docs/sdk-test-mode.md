# SDKs and test mode

The source SDKs cover every shipped public envelope operation: create, send, list, read, artifacts, templates, correct, resend and void. Their generic request method also accepts the published API's query options and bodies. JavaScript and TypeScript use the same client with declarations; Python uses only the standard library. Install the local JavaScript package from `./sdk/javascript` or the Python package from `./sdk/python`.

Keep keys in a server process. An owner, admin or permitted sender mints a key through the ordinary native key-management door with `mode` set to `test`; omit it or choose `live` for production. The key is revealed once. Both modes retain the same scoped, bound-member authority, expiry, rotation, revocation, request and per-key send limits and API sending policy. Rotation preserves mode. A key can see or change only envelopes of its own mode.

Test preparation watermarks each PDF, including ordered documents, template content and supplements, with “TEST MODE - NON-BINDING”. The marker is retained in the envelope and audit evidence. Production reports, envelope usage and policy-send allowance exclude these records. Test invitations and notices are cancelled before external delivery, SMS dispatch excludes test records, and automatic filing creates no jobs. There are no webhook delivery doors today; API-002 must retain mode isolation before adding one.

Test clients can prepare, send, poll, download, correct, resend and void their isolated envelopes. Real recipient signing is refused: a test envelope cannot collect a binding signature. Sending does not deliver an invitation. Deferred external delivery is unavailable in test mode. Test records cannot be turned into production templates; copying retains test mode. The operator detail identifies test records explicitly.

Run `./examples/test-mode.mjs`, `./examples/test-mode.mts` or `./examples/test-mode.py` against a test key and a JSON envelope definition. The JavaScript and Python command examples take the definition filename as their first argument and read the installation origin and test key from `INKWELL_ORIGIN` and `INKWELL_TEST_KEY`. The TypeScript example exports a typed function taking those inputs directly. Reuse a command ID when retrying a mutation whose response was lost; clients never retry a mutation automatically or follow a redirect with the credential.

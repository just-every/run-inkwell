# Salesforce connector

An installation administrator configures `SALESFORCE_INSTANCE_URL`, `SALESFORCE_ACCOUNT_ID` and `SALESFORCE_ACCESS_TOKEN` as private Worker bindings. The instance must be its exact HTTPS Salesforce My Domain origin. The organization identifier must match that credential. Keep the credential outside business records and exports. Connected-app provisioning and live interoperability require separate qualification; the committed journeys use a Salesforce network-edge fake.

Provide text fields named `Inkwell_Status__c`, `Inkwell_Envelope_Id__c`, `Inkwell_Completed_At__c`, `Inkwell_Signed_SHA256__c` and `Inkwell_Key_Fields__c` on each supported Opportunity, Account or Contact object. The key-fields field holds JSON and must have room for the template's executed values. The credential needs access to the selected source fields, contact queries and these completion fields, plus Salesforce Files creation and reads. A missing field or refused provider operation holds completion visibly; it never counts as delivery.

In Settings, an owner or admin authorizes contact imports into the existing shared contact book. The confirmation identifies the source scope, fields, destination readers, update behavior and cadence. Import progress can be continued page by page. Local edits remain intact until an administrator chooses which contact to keep. Revoking an authorization, losing administrative authority or changing credentials permanently stops that version; a new explicit authorization is required.

Use Prepare from Salesforce to choose an Opportunity, Account or Contact and a template. Map native fields to template field IDs and select read-only values as needed. Contact records can supply their native recipient. Opportunity and Account preparation require explicit recipients. The envelope records each imported field's native source. A CRM owner receives no new envelope access, and follow-up still needs its own per-envelope grant.

Preparing a draft sends no invitation. Requesting an integration send requires the account's integration sending policy and all native approval, template and credential checks. Completion returns status, envelope reference, completion time, executed key fields and the signed PDF fingerprint to the same record. Salesforce Files receives the exact signed PDF, with the record attachment created as part of the upload. No provider credential is copied into the record.

If a provider response is lost, completion shows an unconfirmed result. Reconcile completion checks the same record and the exact file bytes before continuing. An uncertain file upload is never blindly repeated. Changed or retired authority remains stopped, and conflicting bytes are refused. Native erasure removes connector custody and prevents replay of that preparation. Restoring business records preserves field provenance but restores no Salesforce authorization. Files already transferred into Salesforce remain under Salesforce custody; native erasure does not claim provider-side deletion.

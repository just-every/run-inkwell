# Bulk send

Open Templates, then Bulk send. Choose a template and upload UTF-8 CSV or an XLSX workbook containing values. The first worksheet is used; formulas must be replaced with values. Upload at most 1,000 data rows and 2 MB of compressed input. Expanded workbook content is bounded to prevent oversized uploads. No spreadsheet code runs.

For a single template role, use `name` and `email` columns. Multiple roles use their exact role name followed by `.name` and `.email`, for example `Customer.name`. Include `.phone` for phone authentication and `.accessCode` where the role requires it, with the same role prefix. A column matching a business field ID supplies that field's prefill value, recorded as coming from the bulk spreadsheet. Signature fields cannot be prefilled. Access-code cells are sealed in pending batch and saved-list custody and masked in previews; released envelopes retain the ordinary keyed access-code hash.

Preview validates every row against the frozen template before sending. Invalid rows show their reason and are skipped. Confirm eligibility once for the whole batch. The browser processes valid rows in small resumable groups; reopening an approved batch and choosing Resume continues without another eligibility approval. Closing the browser pauses unprocessed rows. Retrying never creates another envelope for an already processed row.

Each envelope records the batch name, row and approval time, plus the ordinary person's authority, sending-policy versions and definition fingerprint. Bulk uses its own effective sending policy. Every row rechecks the policy, principal and template in the invitation transaction. Template or policy changes hold remaining rows; turning a policy back on does not resume a held batch. Create and review a new preview. Existing internal approval rules still apply.

Refresh row statuses to see signing progress. Open a row to use the ordinary resend, unsigned-recipient correction and void controls, under their usual permissions. Save a recipient list and select it for another batch without uploading again. Lists and batch processing state belong to the installation, like the contact book; they are excluded from installation archives. Erasing a document removes its source row data and holds the remaining batch. Each envelope's immutable batch provenance travels with its document custody, and restoring an archive never restores active batch authority.
